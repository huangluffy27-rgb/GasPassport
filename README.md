# GasPassport

**给还没上线的 Monad 合约，先算清楚每个函数该留多少 gas。**

现在的常见做法是拍一个“3 倍余量”。在 Monad 上这会直接多付钱：gas 按 limit 扣，不退。GasPassport 给的是按输入规模分桶、带 99% 覆盖保证的预算表。

> 在线原型：https://huangluffy27-rgb.github.io/GasPassport/ —— 连接钱包、查预算表、链上实测页对齐；报告页在 `/report.html`。

一个真实例子，32 人空投：

- 散列映射要 952,286 gas，页对齐只要 711,130，省 **25%**
- 如果拍 3 倍余量，会多付 **160% 以上**
- 合约还没部署时，`eth_estimateGas` 算不了这个函数；我们用状态覆盖先跑出来

## 为什么不能直接用 eth_estimateGas？

| 场景 | 能直接用吗 | 说明 |
|---|---|---|
| 部署交易的 gas | 能 | 发 `data=创建字节码`、没有 `to` 的请求即可 |
| 单笔函数调用 | 能 | 合约已部署、状态确定时，请直接用它 |
| 函数还没部署 | 不能 | 没有地址可调用；我们用 state override 在未部署字节码上跑函数 |
| 批量 / 代付 / AA | 不适合 | 逐笔模拟延迟叠加；预算表一次认证、运行时查表 |
| 输入签名后才确定 | 不能 | 不知道参数估不了；按输入规模分桶，每桶一个上限 |
| 状态漂移与并发 | 不够 | 只反映当前状态；预算表给的是分布上的覆盖保证 |

所以这个工具不跟 `estimateGas` 抢「单笔预估」，只补它覆盖不到的场景。

## 方法

1. **测试网原生采样**：把目标合约的运行时字节码通过 `eth_estimateGas` 的 state override 挂到 Monad 测试网地址上模拟调用，不发交易、不需要私钥。共 1,536 条样本，gas 全部来自节点，不混用本地 EVM 口径。
2. **条件共形预测**：按输入规模分桶，桶边界由动态规划在校准集上选出（最小化期望超付），偶数 iter 做校准、奇数 iter 做留出测试。上限取共形分位数（第 ⌈(n+1)×0.99⌉ 小），得到有限样本、分布无关的 99% 覆盖保证。
3. **极值理论外推**：对超过 80% 分位的尾部拟合广义帕累托分布（矩估计），外推 99.9% 分位并给 bootstrap 90% 区间——样本量撑不起 99.9% 时，这是唯一诚实的外推方式。
4. **页成本测量**：用 `vm.record` / `vm.accesses` 从真实写入轨迹统计 128 槽页数，再看同页与跨页的 gas 差。

### 进阶实验

**CV+ 比率共形**：5 折交叉验证的折外预测做归一化分数 `gas / pred`，上限随输入规模平滑变化。

| 目标 | 分桶期望上限 | CV+ 期望上限 | 收紧 | 留出覆盖 |
|---|---|---|---|---|
| PageWriter | 1,145,039 | 987,210 | 13.8% | 100% |
| BatchAirdrop | 590,562 | 515,967 | 12.6% | 100% |

**自动阈值**：在 50%–90% 分位里选 ξ 最稳的阈值。两个目标的 ξ 都为负（有界尾），自动阈值与固定 80% 的 99.9% 估计相差不到 1%——尾部不重时，阈值选择不敏感，外推会退化到观测最大值。

**顺序停止**：检查点 16/32/64/128/256，并集校正 + 连续两次变化 ≤5% 即停，同时要求样本数 ≥ 1/α−1。PageWriter 在 128 个样本停止，上限与固定 256 相同（1,855,180），省 50% 采样；这是工程早停准则，不是逐时刻有效的置信序列。

**页感知布局建议**：

| 位置 | 建议 | 页数 | gas 变化 |
|---|---|---|---|
| PageWriter.writeScattered | `_slots[i*128]` → `_slots[i]` | 64 → 1 | 1,855,180 → 1,163,725（−37%） |
| BatchAirdrop.airdrop | 映射 → packed `Entry[]` 追加记录（已实现 `AlignedAirdrop`） | 32 → 1 | 952,298 → 711,142（−25.3%） |
| 通用热状态 | 按 128 槽对齐同一次调用必读写的字段 | k → 1..2 | 每少一页省 10,975 |

### 硬件层含义

128 槽 × 32 字节 = 4,096 字节，正好是 OS 页、SSD 页和一次 NVMe 随机读的粒度。页成本不只是 gas 规则，也是内存层次与存储 I/O 的成本。

| 措施 | 预计收益（含假设） |
|---|---|
| 热状态页对齐（64 页 → 1 页） | gas −59.4%（实测 691,455）；每次调用状态页流量 256KB → 4KB（−98%） |
| 写合并 / 批处理 | 存储型函数 gas −10–40%（假设批内地址可合并） |
| 页感知存储布局 | gas −20–60%，随机读 IOPS 降一个量级 |
| 大页 / 预取（节点层） | 节点级 5–15%，协议层不可控 |
| GPU / 并行 EVM 采样 | 采样吞吐 10–100×，不影响链上 gas |

按 10k TPS、每笔 64 页散写估算（上限口径）：状态页流量约 2.56 GB/s、随机读约 64 万 IOPS；页对齐后约 40 MB/s、1 万 IOPS。端到端 TPS 提升取决于节点是否卡在存储：乐观 20–50%，保守 1.5–2×。

完整论证、可行性矩阵、经济性估算与验证计划见 [docs/硬件层改进可行性分析.md](docs/硬件层改进可行性分析.md)。

### 真实交易校准

部署 `PageWriter` 后发了 6 笔真实交易：

- `0.97× estimateGas` 全部回滚，`1.00×` 全部成功 → **estimateGas 就是最小可行 limit**
- 回执 `gasUsed` 恒等于 `gasLimit`（Monad 按 limit 扣费），所以真实成本只能二分试探，不能直接读回执

dApp 端三轮 12 笔真实交易（32/64 人空投 + 低成本部署）的完整哈希、费用拆分与部署优化见 [docs/链上实测总结.md](docs/链上实测总结.md)。

## 快速开始

```bash
# 1. 编译与本地对照实验（首次需 forge install foundry-rs/forge-std）
cd contracts
forge test --match-path test/GasPassport.t.sol

# 2. 测试网原生采样（需要 viem）
cd ..
npm i viem --no-save
node scripts/sample_testnet.mjs

# 3. 生成报告
cd app
npm install
npm run build
node dist/index.js

# 4. dApp 原型（输出到 docs/）
cd ../dapp
npm install
npm run build
```

## 口径与限制

- 认证上限是 99% 覆盖，不是 100%；极端输入仍可能超出，超出即整笔失败且照扣 limit。
- 分桶边界是人为选的（1–8 / 9–16 / 17–32 / 33–64），换合约需要重新定义桶。
- 页数来自当前交易的写入轨迹，跨交易的状态预热不在统计范围内。
- EVT 外推在样本尾部不够重时会退化到观测最大值，这是有意的保守处理。
